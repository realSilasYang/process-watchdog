# 发布流程

1. 更新 `VERSION`、主脚本 Ahk2Exe 文件版本和 `CHANGELOG.md`。
2. 确认仓库不是浅克隆并已取得全部分支和标签。运行 `tests/verify.ps1`；该入口
   会使用锁定版本的 Gitleaks 扫描完整历史，并拒绝曾被提交的个人运行配置、临时
   探针、凭据及当前发布文本中的本机路径。
3. 运行
   `tests/run-gui-tests.ps1 -SoakSeconds 300`；发布前的完整 UI 场景压力测试
   不得缩短。
4. 运行 `tests/reproducible-build.ps1`，保存脚本输出的最终 SHA-256；两次
   ZIP 或独立 SBOM 构建哈希不同，或 `SHA256SUMS.txt` 不匹配时不得发布。
5. 检查发行目录包含 AutoHotkey 许可证和与锁定提交完全对应的源码归档，并确认
   二进制、源码、依赖和测试工具均出现在工具链锁或 SPDX SBOM 中。
6. 在人工 GUI 矩阵中检查受影响的 Windows 与 DPI 组合；未完成的物理组合必须在
   Release 说明中列出，不能用自动化结果代替。
7. 提交全部源码、锁定文件、测试和文档，确保工作区可从 Git 重建。
8. 创建与 `VERSION` 完全一致、且指向已验证提交的标签，例如 `v0.1.0`。
9. Release 工作流重新执行完整验证、短时 GUI 压力测试和双次可复现构建，
   为 ZIP、独立 SBOM 与 `SHA256SUMS.txt` 生成构建溯源证明后再发布。

发布包不签名。若以后加入代码签名，应在确定性未签名构建之后执行，并分别保存
未签名构建哈希、签名产物哈希和签名证书信息。
