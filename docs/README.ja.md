Process Watchdog Assistant は、現在の Windows デスクトップ セッションで長時間動かし続けたいアプリ、スクリプト、ショートカット向けの常駐ツールです。対象が予期せず終了したときは、「停止を確認できた状態」と「一時的に判定できない状態」を区別しながら慎重に自動復旧し、重複起動や誤起動を防ぎます。判定、設定、ログはすべてローカルに残ります。AutoHotkey v2 x64 で構築され、Windows 10 と Windows 11 に対応しています。

実行中かどうかをプロセス名だけで判断することはありません。実行ファイルの完全なパス、プロセス作成時の識別情報、ショートカットの実体、コマンドラインの証拠を組み合わせます。証拠が足りない場合は次回の確認を待ち、「一時的に不明」を停止と見なして別のインスタンスを起動することはありません。

ライト／ダーク表示、自動復旧、アップデート保護、実行ログ、元に戻す／やり直し、表示名とアイコンのカスタマイズに対応しています。Windows x64 配布パッケージには SPDX SBOM、SHA-256 チェックサム、ビルド来歴も含まれます。

# 画面概要

<p align="center">
  <img src="images/process-watchdog-overview.png" alt="プロセス監視アシスタントのメイン画面" width="100%">
</p>

メイン画面には監視対象の順序、アプリアイコン、名前、権限要件、現在の状態がまとまっています。上部のコマンドバーから追加、削除、一時停止、設定、ヘルプ情報、寄付を利用でき、ヘルプ情報から使用説明または実行ログを開けます。下部には実行中、復旧中、更新中、一時停止、失敗の件数が表示され、異常状態の判定根拠は実行ログで確認できます。

## 主な機能

- EXE、AHK、Python、JavaScript、PowerShell、BAT、CMD、LNK を監視。
- `Running`、`Stopped`、`Unknown` の 3 状態で確認し、不明な状態から無条件に再起動しません。
- 対象ごとに独立したコントローラー、世代、タスクトークンを保持。停止、削除、パス変更後は古いコールバックが直ちに無効になります。
- 管理者権限を対象ごとに指定可能。実行中のインスタンスの権限が足りない場合は通知し、次回の監視起動では設定どおり昇格します。
- アップデート保護は既定で無効。オンにすると、更新プロセス、親子関係、インストール先の変化、ファイルの安定性を組み合わせて監視の一時停止と再開を判断します。
- 設定はアトミックに置き換えます。解析できない監視レコードは黙って捨てず、`[Recovery]` に退避します。
- アプリ検索には Everything サービスだけを使用し、内蔵の全ドライブ検索や件数上限は設けません。大量の結果は短い単位で追加し、アイコン取得による画面の長時間停止を防ぎます。
- 簡体字中国語、繁体字中国語（香港）、繁体字中国語（台湾）、英語、日本語、ベトナム語、韓国語、スペイン語、フランス語、ブラジル ポルトガル語、ロシア語、ドイツ語、イタリア語に対応。既定では Windows の表示言語に従い、未対応言語は英語に戻ります。「全般」から手動でも選べます。言語と本文フォントは保存直後に現在のプロセスへ反映され、監視タスクの停止や再初期化は行いません。
- 「言語の既定に従う」では PingFang、SF Pro Text、Harano Aji Gothic、Apple SD Gothic Neo を優先します。端末にない場合は、同梱された商用配布許諾済みまたは OFL のフォントをプロセス内だけで読み込み、それでも使えなければ対応する Noto フォントへ移ります。本文フォントは本文、入力欄、一覧、「バージョン情報」に適用し、ボタン、設定タブ、メイン画面下部は現在の言語に対応する Windows UI フォントの太字を使います。
- ライト／ダーク表示、子ウィンドウの独立した最小化、DPI 変更時のアイコン再構築、角丸ボタン、カスタムアイコンに対応。
- 診断パッケージはローカルでのみ作成し、自動送信しません。正式な成果物は出所と完全性を個別に検証できます。

## 対象範囲

現在の Windows デスクトップ セッションで継続実行し、予期しない終了後に自動復旧したい通常のアプリ、スクリプト、ショートカットが対象です。次のものは対象外です。

- Windows サービス、ドライバー、カーネル コンポーネント、ユーザー セッションをまたぐサービス。
- Windows 7、32 ビット版 Windows、Windows 以外の環境。
- ハード リアルタイム、高可用性クラスター、セキュリティ分離を担うプロセス オーケストレーション。
- 不明なプロセス状態をすべて強制的に停止扱いにする復旧方針。

Windows 11 の実機で 200% DPI の完全な GUI 自動テストを記録し、100% と 300% の描画計算は回帰テストで確認しています。各倍率での手動視覚確認、モニター間の連続 DPI 変更、高コントラストは未検証であり、コードだけから合格とみなしてはいけません。[GUI 検証記録](../tests/gui/VALIDATION-EVIDENCE.en.md)と[互換性と既知の制限](en/compatibility.md)を参照してください。

# ユーザーガイド

## 1. インストールと初回起動

1. [Releases](https://github.com/realSilasYang/process-watchdog/releases) から、単体 EXE、完全なポータブル ZIP、完全なソース ZIP のいずれかを選びます。
2. 単体 EXE は AutoHotkey 不要で、初回起動時に検証済みの内容を `%LOCALAPPDATA%\ProcessWatchdog\Standalone` へ配置します。ポータブル ZIP は完全に展開した任意のフォルダーで動作し、ソース ZIP は AutoHotkey v2 x64 が必要です。
3. `进程守护小助手.exe` を実行します。管理者権限を要求した後、設定に応じてメイン画面を表示するか、通知領域に常駐します。
4. ［追加］で対象を選ぶか、対応ファイルをメイン画面へドラッグ＆ドロップします。
5. ［ログ］を開くと、識別根拠、状態確認、復旧試行、アップデート信号を確認できます。

ソースから実行する場合は AutoHotkey v2 x64 をインストールし、`进程守护小助手.ahk` を実行します。Git でリポジトリをクローンする場合は Git LFS もインストールし、`git lfs pull` を実行して、ポインターではなく完全なフォント ファイルを取得してください。Release に添付されるソース ZIP にはこれらのファイルが含まれているため、Git LFS は不要です。正式版には完全なリリース試験を通過した AutoHotkey ランタイムが組み込まれているため、通常の利用者は別途インストールする必要がありません。

### バージョンと実行形態

| 項目 | EXE 版 | ソース版 |
| --- | --- | --- |
| アシスタント | EXE のファイル バージョンを使用し、更新時は配布パッケージ全体を置換 | エントリと同じ場所の `VERSION` を使用し、安全な Git fast-forward またはソース パッケージで更新 |
| AutoHotkey | 組み込み済み。後のアシスタント完全版とともに更新 | ローカルのインタープリターを使用。アシスタントの更新では AutoHotkey を更新しない |
| Ahk2Exe | 正式リリースで EXE を作成する場合だけ使用し、利用者の PC には入らない | 不要 |

「アシスタントが最新版」と「ローカルの AutoHotkey が最新版」は別の意味です。正式リリースの開始時に最新安定版 AutoHotkey と最新公開版 Ahk2Exe を選び、その組み合わせを固定して全試験を完了してから AutoHotkey を EXE に組み込みます。［アシスタント設定 → バージョン情報］では、アシスタントのバージョン、EXE／ソースの別、実際の AutoHotkey バージョンを確認し、手動で更新を確認できます。詳しくは[バージョン、実行形態、更新責任](en/versioning.md)を参照してください。

メイン画面を閉じても通知領域に隠れるだけで、監視は続きます。完全に終了するには通知領域メニューの［終了］を使います。ショートカット、スケジュール起動、アップグレードについては[インストール、更新、削除](en/installation.md)を参照してください。

## 2. 項目の追加と管理

| ボタン | 用途 |
| --- | --- |
| 追加 | 対象を選択、インストール済みアプリを検索、またはフォルダーを一括取り込み。既定ではサブフォルダーも対象 |
| 削除 | 選択した監視対象を削除。複数選択と取り消しに対応 |
| 一時停止／再開 | 自動監視だけを切り替え、現在動いている対象は終了しない。混在選択は項目ごとに反転 |
| 設定 | 全般、監視と起動、停止ポリシー、ログ、バージョン情報を設定 |
| ヘルプ情報 | 組み込みの使用説明、実行ログ、GitHub のフィードバック ページを選択 |
| 寄付 | 継続保守を支援する WeChat Pay と Alipay の QR コードを表示 |

項目には起動エントリ、作業フォルダー、引数、管理者権限の要否を設定できます。LNK は起動エントリとして保持し、解決した実行ファイル パスはプロセス識別用に別途保存します。そのため、インストーラーが作った間接ショートカットを、変わりやすい内部 EXE に置き換える必要はありません。

一覧の右クリック メニューから、ファイルの場所、対象の実行終了、対象パス、プロセス識別と起動設定、管理者権限要件、アップデート保護を操作できます。［実行を終了］は監視も一時停止し、対象が自動的に再起動されないようにします。メイン画面だけの名前とアイコンも変更できますが、対象識別、起動、アップデート保護には影響しません。既定表示のままなら、既定に戻す操作は無効です。

BAT と CMD の項目に限り、［バッチ出力ログを表示］が追加で表示されます。他の種類にはこの項目は表示されません。独立したログ ファイルが作られるのは、本アプリがそのバッチ項目を実際に起動し、標準出力と標準エラー出力を取り込んだ場合だけです。すでに実行中のバッチ プロセスには自動作成されません。

行をドラッグして並べ替えると順序が保存されます。`Ctrl+Z`、`Ctrl+Y`、`Ctrl+Shift+Z` で追加、削除、並べ替え、設定変更を元に戻す／やり直すことができます。左端の番号は表示順に合わせて再採番され、識別、起動、保存データには使いません。例は[よくある利用例](en/quick-start.md)を参照してください。

## 3. 状態と復旧

一覧の状態は、現在得られている証拠と次の処理を表します。アイコンの色だけで結果を判断しないでください。

| 状態 | 意味 |
| --- | --- |
| 実行中 | 対象の識別情報と一致する実行中インスタンスを検出 |
| 実行中（権限不一致） | インスタンスはあるが、設定した管理者権限要件を満たさない |
| プロセス状態を確認中／停止の可能性 | 証拠が不足、または終了直後のため再確認中。直ちに重複起動しない |
| 起動中／再試行カウントダウン | 復旧が必要と確認され、再試行順序に従って次の試行を待機 |
| アップデート中／ファイル安定性を確認中 | 自動起動を止め、更新終了と対象ファイルの安定を待機 |
| 一時停止 | 自動確認と復旧は停止中。対象プロセスは終了しない |
| 停止／起動失敗／待機タイムアウト | 復旧できなかったか確認が必要。正確な証拠と理由はログを参照 |

既定の再試行待機は 1、10、60 秒です。短い順序を使い切ると最後の待機時間を繰り返し、高速な起動ループを防ぎます。削除、一時停止、パス変更、取り消しによって古いスケジュールと非同期結果は無効になります。

## 4. アップデート保護

アップデート保護は既定で無効で、項目ごとに手動で有効にします。

1. 対象を右クリックし、［アップデート保護］を開きます。
2. アップデートの自動検出と起動保護を有効にします。
3. インストール範囲、終了検出時間、ファイル安定待機、最長待機を確認します。
4. 保存後、アプリに通常どおり実際のアップデートを一度行わせます。更新プロセス、親子関係、インストール先の活動、ファイル通知、学習した更新プログラムの特徴から保護開始を判断します。

アップデートを確認すると自動起動を保留し、活動終了後に対象ファイルが安定してから通常監視へ戻ります。判定がタイムアウトした場合や実態と異なる場合は、同じ画面の［アップデート待機を終了して監視を再開］を使えます。再開前にも起動エントリを安全に使えるか確認します。

この機能は汎用インストーラーや Windows サービス管理ツールではありません。ポータブル アプリ、インストール先外の更新プログラム、特殊なランチャーでは、まず実行ログを確認してから範囲やルールを調整してください。

## 5. 設定

| 分類 | 設定内容 |
| --- | --- |
| 全般 | デスクトップ／スタート メニューのショートカット、スケジュール自動起動、2 種類の起動時動作、表示言語、画面本文フォント、テーマ |
| 監視と起動 | プロセス状態の確認間隔、クラッシュ後の自動再起動待機順序、フォルダー取り込み時のサブフォルダー対象化 |
| 停止ポリシー | GUI／CLI アプリの終了タイムアウト、超過後の強制終了許可 |
| ログ | 起動時消去、実行ログ表示上限、バッチログ保持日数、保存先 |
| バージョン情報 | アプリと実行環境のバージョン、今すぐ更新を確認、オープンソース プロジェクトへのリンク |

設定画面は数値範囲を検証します。`watchdog.ini` のコメントは対応する区分と項目の近くに置かれています。エンコード済みフィールドを壊さないよう、なるべく画面から変更してください。詳しくは[設定、バックアップ、復旧](en/configuration.md)を参照してください。

## 6. ログ、診断、プライバシー

［実行ログ］は文字列の選択とコピー、最大化、サイズ変更に対応します。スクロールバーは必要な場合だけ表示され、ログ自体は編集できません。

原因を特定しにくい場合は、ログ画面からローカル診断パッケージを出力できます。アプリ、Windows、AutoHotkey、DPI、リソース ハンドル、監視段階、設定警告、現在のログの要約を含みますが、自動では送信しません。

個人設定は実際の実行フォルダーの `watchdog.ini`、未完了のアップデート セッションは同じ場所の `watchdog.maintenance.ini` に保存されます。ポータブル版とソース版は各エントリ フォルダー、単体 EXE は常に `%LOCALAPPDATA%\ProcessWatchdog\Standalone` を使います。どちらのファイルも配布物には含まれず、更新で上書きされません。

ポータブル EXE とソース エントリは同じフォルダーにある場合だけ状態を共有します。単体 EXE は、ダウンロードした起動ファイルの隣にある設定を使いません。全体の単一インスタンス ロックにより複数形態の同時実行はできず、ショートカットとスケジュール タスクは最後に統合した実際の形態を指します。詳しくは[設定、バックアップ、復旧](en/configuration.md)と[インストール、更新、削除](en/installation.md)を参照してください。

ログと診断には対象パス、起動引数、環境変数が含まれることがあります。公開前に内容を確認し、必要な情報を伏せてください。通常の報告には[構造化 Issue フォーム](https://github.com/realSilasYang/process-watchdog/issues/new/choose)を使い、未修正のセキュリティ問題は非公開の脆弱性報告を利用してください。[ローカル診断](en/diagnostics.md)、[トラブルシューティング](en/troubleshooting.md)、[サポート](../.github/SUPPORT.en.md)も参照してください。

```text
├─ .github/                 Issue、ワークフロー、共同作業用テンプレート
├─ app/                     アプリ状態、画面への接続、各ウィンドウ
├─ assets/                  アイコン、寄付画像、プロセス内フォント
├─ config/                  項目ごとのコメント付き設定例
├─ docs/                    利用、設計、多言語、画像、運営文書
├─ src/                     設定、コア、診断、実行、調査、更新保護、プラットフォーム、UI、自動更新
├─ runtime/                 EXE／ソース共用のバックグラウンド更新ヘルパー
├─ tests/                   コア、GUI、リリース、リポジトリ検証
├─ third_party/             固定した DLL、ライセンス、依存関係一覧
├─ tools/                   ビルド、SBOM、リリース検証、ツールチェーン準備
└─ 进程守护小助手.ahk      構成ルート兼起動エントリ
```

ルート スクリプトはモジュールの読み込み、依存関係の組み立て、アプリの起動だけを担当します。`src` はルートのグローバル `App`、`Main`、`GuiModules` を読みません。`app` が純粋なコア機能を画面、ログ、システム操作へ接続します。[アーキテクチャと正しさの境界](en/architecture.md)も参照してください。

## 2. 正しさの境界

- 対象の識別、起動エントリ、メイン画面の表示カスタマイズは独立し、表示設定が監視判断を変えてはいけません。
- `Running`、`Stopped`、`Unknown` は外部証拠の結果で、停止を確認した場合だけ復旧へ進みます。
- タイマー、メッセージ コールバック、ファイル監視、ワーカー、ウィンドウ、ネイティブ リソースには、繰り返しても安全な解放経路が必要です。
- 設定スナップショット、監視対象、アップデート保護は 1 つのトランザクションで確定し、テストが個人の `watchdog.ini` を読んだり上書きしたりしてはいけません。
- 取り下げた GDI スクリーンショット重ね合わせ式のスムーズ スクロールを再導入せず、ListView とログはネイティブ スクロールを保ちます。
- DPI、アイコン、ダーク モード、ウィンドウ階層、アクセシビリティの主張には実機 Windows と倍率での証拠が必要です。自動試験だけでは実ディスプレイの組み合わせを代替できません。

## 3. 検証コマンド

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\verify.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\verify-windows-integration.ps1 `
  -SoakSeconds 10
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\reproducible-build.ps1
```

`verify.ps1` は依存関係ハッシュ、AHK 構文解析、静的な設計制約、コア試験、リポジトリ境界、Git 全履歴の漏えい、ワークフロー構文、起動動作を確認します。`verify-windows-integration.ps1` は完全なフォントを検証し、実際の Windows コントロールで 13 言語、3 階層のウィンドウ、GDI／USER ハンドル解放を確認します。`reproducible-build.ps1` は 3 形態と SBOM を 2 回構築してチェックサムを比較します。

AutoHotkey と Ahk2Exe はリポジトリに事前固定しません。手動の正式リリースごとに AutoHotkey の最新安定版と Ahk2Exe の最新公開版を調べ、同じ解決済みスナップショットで試験、2 回のビルド、SBOM、梱包を行います。actionlint と Gitleaks など検証専用ツールは固定版です。実際のバージョン、入手元、コミット、SHA-256 はリリースに保存します。[第三者ソフトウェアの表示](project/THIRD_PARTY_NOTICES.en.md)も参照してください。

## 4. リリースと貢献

利用者に見える変更は、すべての言語版 README と変更履歴へ反映する必要があります。新しいバージョンでは[変更履歴テンプレート](en/changelog-template.md)を使い、コミット文や内部クラス名を並べず、利用者が確認できる追加、改善、修正としてまとめます。

詳しい手順は[リリース手順](en/release-process.md)と[公開前チェックリスト](en/publication-checklist.md)を参照してください。通常の Pull Request でバージョン タグを作成したり、公開済みタグを書き換えたりしてはいけません。Issue と Pull Request には再現方法、リスク、検証証拠を添え、ウィンドウ、DPI、アイコン、ダーク モードの場合は実際に確認した Windows バージョンと倍率も記載してください。[貢献ガイド](../.github/CONTRIBUTING.en.md)と[プロジェクト運営](project/GOVERNANCE.en.md)も参照してください。
