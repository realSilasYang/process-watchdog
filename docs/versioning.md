# 版本、运行方式与更新责任

**简体中文** | [English](en/versioning.md)

## 先分清三个版本

小助手涉及三个容易混淆、但用途完全不同的版本：

| 名称 | 作用 | 普通用户是否需要维护 |
| --- | --- | --- |
| 小助手版本 | 表示功能、配置格式和发布内容；EXE 版写入文件版本，源码版读取 `VERSION` | 通过小助手自身更新或手动更换发行包 |
| AutoHotkey 版本 | 实际执行 AHK 代码的 x64 运行时 | EXE 版不需要；源码版需要自行安装和升级 AutoHotkey v2 x64 |
| Ahk2Exe 版本 | 只在 GitHub Actions 中把源码与 AutoHotkey 运行时封装为 EXE | 不需要安装，也不会随小助手进入用户电脑 |

因此，“小助手已经是最新版本”只表示当前小助手版本与最新正式 Release 一致，
不表示源码版电脑上的 AutoHotkey 一定是最新版。反过来，单独升级本机 AutoHotkey
也不会改变小助手版本或功能变更日志。

## 三种下载的区别

| 项目 | 独立 EXE | 完整便携 ZIP | 完整源码 ZIP |
| --- | --- | --- | --- |
| 启动入口 | 任意位置的单文件引导器，实际启动 `LOCALAPPDATA` 中的正式 EXE | 完整解压目录中的 `进程守护小助手.exe` | 本机 `AutoHotkey64.exe` 加 `进程守护小助手.ahk` |
| AutoHotkey 来源 | 内嵌并安装在稳定目录 | 已封装在 EXE 中 | 使用电脑当前安装的 AutoHotkey v2 x64 |
| 是否需要单独安装 AutoHotkey | 不需要 | 不需要 | 需要 |
| 小助手自动更新 | 更新稳定目录中的内层编译版；旧引导器不会降级新安装 | 更新当前解压目录中的编译版 | Git 仓库安全快速前进，或下载并校验源码发行包；仍用原解释器校验和重启 |
| 是否随小助手更新 AutoHotkey | 会 | 会 | 不会；本机解释器由用户单独维护 |
| 配置目录 | `%LOCALAPPDATA%\ProcessWatchdog\Standalone` | 当前便携 EXE 所在目录 | 当前 AHK 入口所在目录 |

三种下载使用相同的功能代码和配置格式，但配置只会在相同的实际运行目录中共享。
下载的独立 EXE 引导器旁不会产生或读取个人配置；便携 EXE 与源码入口放在同一目录
时会共用个人状态、发行资源和更新清单。全局单实例锁阻止不同形态同时运行。需要长期
保留多套安装时，应使用不同的实际运行目录，并在“通用”中为日常使用的那一套重新
创建或切换快捷方式和计划任务。

更新只接受严格的 `主版本.次版本.修订版本` 正式版本，目标必须高于当前版本。下载包
会核对校验和、运行形态、入口版本和受管路径；新版先执行无界面快速校验，正式进程
还必须完成配置读取、窗口装配和守护计时器启动并返回就绪信号。任一阶段失败时，
发行包安装恢复原文件，Git 源码安装恢复原提交；启动期间发生迁移的两个个人配置也会
逐字节恢复到更新前状态，然后重新启动旧版本。
Git worktree 的 `.git` 文件与普通克隆的 `.git` 目录都会被正确识别；浅克隆会先补齐
升级到目标标签所需的历史。

## 正式发行怎样选择工具版本

仓库不预先锁死未来发行要使用的 AutoHotkey 和 Ahk2Exe 版本。维护者只能从 `main`
手动启动 Release 工作流；工作流开始后会：

1. 查询 AutoHotkey 上游最新稳定版。
2. 查询 Ahk2Exe 上游最新发布版；这里允许上游标记为预发布，但拒绝草稿。
3. 下载二进制、许可证和对应 AutoHotkey 完整源码，计算 SHA-256，并冻结为本次
   `toolchain.resolved.json`。
4. 使用同一份冻结快照完成核心验证、真实 GUI 冒烟、资源压力测试和两次可复现构建。
5. 只有全部通过，才把该 AutoHotkey 运行时封装进 EXE；三个用户版本发布到
   GitHub Release，校验清单与 SBOM 保留在完整 Actions 构建产物中，并为三个用户
   版本生成构建溯源证明。

这意味着官方 EXE 使用的是“该次小助手发布开始时选定并通过测试的最新稳定
AutoHotkey”，不是以后始终自动跟随上游变化。上游发布新版后，只有下一次小助手正式
发布重新解析、测试并生成新包，用户的内嵌运行时才会随小助手更新。

## 用户在哪里查看

- 打开“小助手设置 → 关于”，可看到当前小助手版本、EXE／源码运行形态和实际
  AutoHotkey 版本；更新检查按钮也在此页。
- 每次启动都会把同一份版本摘要写入运行日志，反馈问题时无需猜测运行的是哪一套。
- EXE 文件属性中的文件版本是编译版的小助手版本；源码版以入口目录中的 `VERSION`
  为准。
- 正式 EXE 包中的 `build-metadata/toolchain.resolved.json` 记录该包实际使用的
  AutoHotkey、Ahk2Exe、下载来源、提交和哈希；`SBOM.spdx.json` 记录依赖关系。
- 本地诊断包的 `environment.txt` 同时记录小助手、AutoHotkey、编译状态和位数。

普通用户应优先使用完整 Windows x64 ZIP；它不要求另装 AutoHotkey。只有需要阅读、
修改或直接运行 AHK 源码时，才选择源码方式并自行维护 AutoHotkey v2 x64。
