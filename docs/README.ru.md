Помощник наблюдения за процессами предназначен для настольных приложений, сценариев и ярлыков, которые должны долго оставаться доступными в текущем сеансе Windows. После неожиданного завершения он автоматически и осмотрительно восстанавливает цель, отличая подтверждённую остановку от временно неопределённого состояния, чтобы не запускать ошибочные или повторные экземпляры. Все решения, настройки и журналы остаются на компьютере. Проект создан на AutoHotkey v2 x64 и поддерживает Windows 10 и Windows 11.

Помощник не считает процесс работающим лишь по его имени. Он сопоставляет полный путь, идентификатор создания процесса, фактическую цель ярлыка и данные командной строки. Если доказательств недостаточно, он ждёт следующей проверки, а не принимает неизвестное состояние за остановку.

В проекте есть светлая и тёмная темы, автоматическое восстановление, защита при обновлении программ, журнал работы, отмена и повтор действий, настраиваемые имена и значки. Пакет Windows x64 сопровождается SPDX SBOM, контрольными суммами SHA-256 и сведениями о происхождении сборки.

# Обзор интерфейса

<p align="center">
  <img src="images/process-watchdog-overview.png" alt="Главное окно Process Watchdog Assistant" width="100%">
</p>

В главном окне собраны порядок объектов наблюдения, значок приложения, имя, требования к правам и текущее состояние. Верхняя панель позволяет добавлять, удалять и приостанавливать объекты, открывать настройки, справку и окно пожертвований; из справки доступны руководство и журнал работы. Нижняя строка показывает число работающих, восстанавливаемых, обновляемых, приостановленных и неисправных объектов, а журнал объясняет доказательства каждого необычного состояния.

## Основные возможности

- Наблюдение за целями EXE, AHK, Python, JavaScript, PowerShell, BAT, CMD и LNK.
- Три результата проверки: `Running`, `Stopped`, `Unknown`. Неизвестное состояние никогда не вызывает безусловный перезапуск.
- У каждой цели есть собственный контроллер, поколение и токены задач. Старые обратные вызовы сразу теряют силу после приостановки, удаления или смены пути.
- Можно потребовать права администратора. Если права запущенного экземпляра не соответствуют настройке, помощник сообщает об этом, а следующий запуск под наблюдением выполняет с повышением прав.
- Защита обновления по умолчанию выключена. После включения она учитывает процессы обновления, связи родитель-потомок, активность каталога установки и стабильность файлов, прежде чем приостановить или возобновить наблюдение.
- Конфигурация заменяется атомарно. Неразбираемые записи перемещаются в `[Recovery]`, а не теряются без уведомления.
- Поиск приложений использует только службу Everything, без встроенного сканирования всего диска и без ограничения числа результатов. Большие наборы добавляются короткими порциями, чтобы извлечение значков не блокировало интерфейс.
- Поддерживаются упрощённый китайский, традиционный китайский для Гонконга, традиционный китайский для Тайваня, английский, японский, вьетнамский, корейский, испанский, французский, бразильский португальский, русский, немецкий и итальянский языки. По умолчанию интерфейс следует языку Windows; для неподдерживаемого языка используется английский, а вручную язык выбирается в разделе «Общие». Смена языка и шрифта содержимого сразу применяется в текущем процессе, не останавливая и не переинициализируя задачи наблюдения.
- Режим «По умолчанию для языка» предпочитает PingFang, SF Pro Text, Harano Aji Gothic или Apple SD Gothic Neo. Если шрифта нет, в процесс закрыто загружается поставляемый ресурс с коммерческим разрешением или OFL, затем используется соответствующее семейство Noto. Шрифт содержимого применяется к тексту, полям, спискам и сведениям «О программе»; кнопки, вкладки и нижняя строка всегда используют полужирный системный UI-шрифт Windows для текущего языка.
- Светлая и тёмная темы поддерживают независимое сворачивание дочерних окон, перестроение значков при изменении DPI, скруглённые кнопки и пользовательские значки.
- Диагностический пакет создаётся только локально и не отправляется автоматически; официальные артефакты можно независимо проверить.

## Область применения

Помощник подходит обычным приложениям, сценариям и ярлыкам, которые должны работать в текущем сеансе рабочего стола Windows и восстанавливаться после неожиданного завершения. За рамками проекта остаются:

- Службы Windows, драйверы, компоненты ядра и службы, работающие между сеансами пользователей.
- Windows 7, 32-разрядная Windows и другие операционные системы.
- Системы жёсткого реального времени, кластеры высокой доступности и оркестрация процессов, требующая изоляции безопасности.
- Агрессивная политика, принудительно считающая любое неизвестное состояние остановкой.

Полный прогон автоматизации GUI документирован в Windows 11 при реальном DPI 200%, а расчёты рендеринга для 100% и 300% покрыты регрессионными тестами. Ручная визуальная проверка на каждом масштабе, непрерывные переходы DPI между мониторами и высокий контраст пока не проверены и не должны выводиться только из кода. См. [запись проверки GUI](../tests/gui/VALIDATION-EVIDENCE.en.md) и [Совместимость и известные ограничения](en/compatibility.md).

# Руководство пользователя

## 1. Установка и первый запуск

1. На странице [Releases](https://github.com/realSilasYang/process-watchdog/releases) выберите полный переносимый ZIP или полный ZIP с исходным кодом. Необязательный пакет шрифтов не является третьей версией программы.
2. Переносимый ZIP работает после полной распаковки и не требует отдельной установки AutoHotkey; для ZIP с исходным кодом требуется AutoHotkey v2 x64. Шрифты нужно установить в Windows, но для запуска программы они не обязательны; для поиска приложений также нужна [последняя официальная версия Everything](https://www.voidtools.com/downloads/).
3. Запустите `进程守护小助手.exe`. Приложение запросит права администратора и, в зависимости от настроек, покажет главное окно либо останется в области уведомлений.
4. Нажмите «Добавить», чтобы выбрать цель, либо перетащите поддерживаемый файл в главное окно.
5. Откройте журнал, чтобы увидеть фактически использованные данные идентификации, проверки состояния, попытки восстановления и сигналы обновления.

Для запуска из исходного кода установите AutoHotkey v2 x64 и выполните `进程守护小助手.ahk`. Если репозиторий клонирован через Git, установите также Git LFS и выполните `git lfs pull`, чтобы получить полные файлы шрифтов, а не указатели LFS. ZIP с исходным кодом, приложенный к выпуску, уже содержит эти ресурсы и не требует Git LFS. Официальная сборка уже содержит среду AutoHotkey, прошедшую полный набор проверок выпуска, поэтому обычному пользователю отдельная установка не нужна.

### Версии и способы запуска

| Компонент | Версия EXE | Исходный код |
| --- | --- | --- |
| Помощник | Читает версию файла EXE; обновление заменяет весь пакет | Читает `VERSION` рядом с точкой входа; обновляется безопасной перемоткой Git или пакетом исходников |
| AutoHotkey | Встроен и обновляется вместе со следующим полным пакетом помощника | Использует локальный интерпретатор; обновление помощника не обновляет AutoHotkey |
| Ahk2Exe | Используется только для создания официального EXE и не устанавливается пользователям | Не требуется |

«Помощник обновлён» и «локальный AutoHotkey обновлён» — разные утверждения. В начале каждого официального выпуска выбираются последняя стабильная версия AutoHotkey и последний опубликованный Ahk2Exe, выбор фиксируется, и весь набор тестов выполняется до встраивания AutoHotkey. «Настройки помощника → О программе» показывает версию помощника, способ EXE/исходники и реальную версию AutoHotkey, а также позволяет проверить обновления вручную. См. [Версии, способы запуска и ответственность за обновление](en/versioning.md).

Закрытие главного окна лишь скрывает его в области уведомлений; наблюдение продолжается. Для полного завершения выберите «Выход» в меню значка. Подробнее о ярлыках, плановом запуске и обновлении см. [Установка, обновление и удаление](en/installation.md).

## 2. Добавление и управление объектами

| Кнопка | Назначение |
| --- | --- |
| Добавить | Выбрать цель, найти установленное приложение или импортировать папку; вложенные папки включены по умолчанию |
| Удалить | Удалить выбранные объекты; поддерживаются множественный выбор и отмена |
| Приостановить / Возобновить | Изменить только автоматическое наблюдение, не закрывая работающую цель; смешанный выбор переключается поэлементно |
| Настройки | Настроить Общие, Наблюдение и запуск, Политику остановки, Журналы и О программе |
| Справка | Выбрать встроенное руководство, журнал работы или страницу отзывов GitHub |
| Поддержать | Показать QR-коды WeChat Pay и Alipay для поддержки сопровождения |

Для объекта задаются точка запуска, рабочий каталог, аргументы и требование прав администратора. LNK остаётся точкой запуска, а фактический путь программы хранится отдельно для идентификации процесса. Поэтому косвенный ярлык, созданный установщиком, не нужно вручную заменять меняющимся внутренним EXE.

Контекстное меню позволяет открыть расположение, завершить работу цели, изменить путь, настроить идентификацию процесса и параметры запуска, переключить требование администратора, настроить защиту и изменить имя или значок только в главном окне. Команда завершения также приостанавливает наблюдение, чтобы цель не запускалась автоматически. Представление не влияет на идентификацию, запуск и защиту. Если уже используются значения по умолчанию, их восстановление недоступно.

Только для объектов BAT и CMD дополнительно показывается команда «Открыть журнал вывода пакетного файла»; для целей других типов её нет. Отдельный файл журнала создаётся лишь тогда, когда помощник сам запускает этот объект и перенаправляет его стандартный вывод и поток ошибок. Для уже работающего пакетного процесса файл автоматически не создаётся.

Перетаскивайте строки для изменения порядка — он сохраняется. `Ctrl+Z`, `Ctrl+Y` и `Ctrl+Shift+Z` отменяют или повторяют добавление, удаление, сортировку и настройки. Номер слева заново вычисляется по видимому порядку и не участвует в идентификации, запуске и хранении. См. [Типичные сценарии](en/quick-start.md).

## 3. Состояния и восстановление

Состояние в списке описывает доступные доказательства и следующий шаг. Не делайте вывод только по цвету значка.

| Состояние | Значение |
| --- | --- |
| Работает | Найден работающий экземпляр, совпадающий с идентичностью цели |
| Работает (права не совпадают) | Экземпляр существует, но не соответствует требованию администратора |
| Ожидание состояния / Возможно остановлен | Доказательств недостаточно или выход замечен только что; выполняется повторная проверка без дублирующего запуска |
| Запуск / Обратный отсчёт | Необходимость восстановления подтверждена, следующая попытка ждёт согласно последовательности |
| Обновление / Проверка стабильности | Автозапуск ждёт завершения активности и стабилизации файлов |
| Приостановлено | Автоматические проверки и восстановление приостановлены, но целевой процесс не закрыт |
| Остановлен / Ошибка запуска / Истёк срок | Восстановление не удалось или нужно подтверждение; доказательства и причина указаны в журнале |

Задержки по умолчанию — 1, 10 и 60 секунд. После быстрой последовательности последнее значение повторяется, чтобы избежать частого цикла запусков. Удаление, пауза, смена пути и отмена делают недействительными старые задачи и асинхронные результаты.

## 4. Защита при обновлении

Защита по умолчанию выключена и включается отдельно для каждого объекта:

1. Щёлкните цель правой кнопкой и откройте защиту обновления.
2. Включите автоматическое распознавание обновления и защиту запуска.
3. Проверьте область установки, окно обнаружения выхода, ожидание стабильности и максимальное время обновления.
4. Сохраните и позвольте приложению один раз выполнить настоящее обновление обычным способом. Помощник сопоставит процессы обновления, связи родитель-потомок, активность каталогов, уведомления файлов и изученные признаки программы обновления.

После подтверждения обновления автоматический запуск приостанавливается. Обычное наблюдение вернётся лишь после завершения активности и стабилизации файлов. Если обнаружение завершилось по времени или не соответствует действительности, выберите завершение ожидания и возобновление наблюдения. Перед восстановлением безопасность точки запуска проверяется снова.

Это не универсальный установщик и не диспетчер служб Windows. Для переносимых приложений, программ обновления вне каталога и необычных средств запуска сначала изучите журнал, а затем настраивайте область и правила.

## 5. Настройки

| Раздел | Параметры |
| --- | --- |
| Общие | Ярлыки рабочего стола и меню «Пуск», плановый автозапуск, два поведения при запуске, язык, шрифт содержимого и тема |
| Наблюдение и запуск | Интервал проверки процесса, последовательность задержек после сбоя и включение вложенных папок при импорте |
| Политика остановки | Сроки закрытия GUI/CLI-программ и разрешение принудительного завершения после истечения |
| Журналы | Очистка при запуске, предел отображения, срок хранения пакетных журналов и каталог сохранения |
| О программе | Версии приложения и среды, немедленная проверка обновлений и ссылка на открытый проект |

Окно проверяет диапазоны чисел. Комментарии `watchdog.ini` расположены рядом с соответствующими разделами и параметрами; лучше использовать интерфейс, чтобы не повредить закодированные поля. См. [Конфигурация, резервное копирование и восстановление](en/configuration.md).

## 6. Журналы, диагностика и конфиденциальность

В журнале работы можно выделять и копировать текст, разворачивать окно и менять его размер. Полосы прокрутки появляются только при необходимости, а текст нельзя редактировать.

Для сложной проблемы из окна журнала можно экспортировать локальный диагностический пакет. В нём есть сводки о приложении, Windows, AutoHotkey, DPI, дескрипторах ресурсов, этапе наблюдения, предупреждениях конфигурации и текущем журнале, но автоматической отправки нет.

Личная конфигурация хранится в `watchdog.ini` в фактическом каталоге запуска, а незавершённые сеансы — там же в `watchdog.maintenance.ini`. Переносимая и исходная версии используют свой каталог входа. Git игнорирует оба файла, выпуски не включают и не перезаписывают их.

Переносимый EXE и исходная точка входа делят состояние только в одном каталоге; отдельный EXE не использует конфигурацию рядом со скачанным загрузчиком. Общесистемная блокировка запрещает одновременный запуск форм, а ярлыки и плановое задание указывают на последнюю фактически интегрированную форму. См. [Конфигурация, резервное копирование и восстановление](en/configuration.md) и [Установка, обновление и удаление](en/installation.md).

Журналы могут содержать пути, аргументы и переменные среды. Проверьте и скройте чувствительные данные перед публикацией. Для обычного отчёта используйте [структурированные формы Issue](https://github.com/realSilasYang/process-watchdog/issues/new/choose), а для неисправленной уязвимости — закрытый канал. См. [Локальная диагностика](en/diagnostics.md), [Устранение неполадок](en/troubleshooting.md) и [Поддержка](../.github/SUPPORT.en.md).

Корневой сценарий только подключает модули, собирает зависимости и запускает приложение. `src` не читает корневые глобальные `App`, `Main` или `GuiModules`; `app` связывает чистое ядро с окнами, журналами и системными операциями. См. [Архитектура и границы корректности](en/architecture.md).

## 2. Границы корректности

- Идентичность цели, точка запуска и настраиваемое представление независимы; представление не должно менять решение наблюдения.
- `Running`, `Stopped` и `Unknown` — результаты внешних доказательств; восстановление начинается только после подтверждённой остановки.
- Каждый таймер, обратный вызов, наблюдатель, рабочий процесс, окно и нативный ресурс должен иметь идемпотентный путь очистки.
- Снимок конфигурации, объекты и защита обновления фиксируются одной транзакцией; тесты не должны читать или перезаписывать личный `watchdog.ini`.
- Отброшенная плавная прокрутка с наложением снимков GDI не должна возвращаться; ListView и журнал сохраняют нативную прокрутку.
- Заявления о DPI, значках, тёмной теме, иерархии и доступности требуют реальных проверок Windows; автоматизация не заменяет физическую матрицу.

## 3. Команды проверки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\verify.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\verify-windows-integration.ps1 `
  -SoakSeconds 10
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\reproducible-build.ps1
```

`verify.ps1` проверяет хеши, разбор AHK, архитектурные ограничения, тесты ядра, границы репозитория, утечки во всей истории Git, синтаксис процессов и запуск. `verify-windows-integration.ps1` проверяет полные файлы шрифтов, создаёт настоящие элементы Windows и тестирует 13 языков, три уровня окон и освобождение дескрипторов GDI/USER. `reproducible-build.ps1` дважды строит три варианта выпуска и SBOM и сравнивает суммы.

AutoHotkey и Ahk2Exe заранее не закрепляются в репозитории. Каждый ручной выпуск запрашивает последнюю стабильную версию AutoHotkey и последний выпуск Ahk2Exe, фиксирует единый результат и применяет именно его для тестов, двух сборок, SBOM и упаковки. Проверочные инструменты actionlint и Gitleaks остаются закреплёнными. Выпуск хранит фактические версии, источники, коммиты и SHA-256. См. [Сведения о стороннем ПО](project/THIRD_PARTY_NOTICES.en.md).
