# 架构与正确性边界

**简体中文** | [English](en/architecture.md)

本文面向维护者和希望审查守护正确性的贡献者。用户操作请先阅读
[常见使用场景](quick-start.md)和[配置说明](configuration.md)。

## 设计原则

项目把“无法确认目标仍在运行”和“确认目标已经停止”分开处理。探活统一返回
`Running / Stopped / Unknown`；只有可靠的停止证据才能进入恢复流程。任何异步
回调在写回状态前，都必须重新核对目标路径、控制器实例、代际和任务令牌。

主线程只执行快速原生探测和 UI 投影。WMI 命令行查询、文件扫描和批量导入在隐藏
的短生命周期工作进程中执行，以原子结果文件交付；超时、结果不完整、身份不符或
应用退出时，结果整批拒绝。

## 模块边界

- 根入口 `进程守护小助手.ahk` 是组合根，只负责包含模块、装配依赖和启动。
- `app` 组合应用服务，连接运行时适配器、守护命令、日志、系统集成和具体窗口。
- `src/Config` 管理运行设置、布局、监控项、展示配置、升级保护配置和历史快照。
- `src/Update` 协调小助手自身更新的后台进程、原子结果和关闭边界；网络与文件替换
  实现在 `runtime/application-update.ps1`。
- `src/Core` 管理探活结果、单目标控制器、共享调度器、工作门和重试策略。
- `src/Inspection` 管理进程、命令行、快捷方式、文件完整性和目录变化证据。
- `src/Execution` 集中执行启动、窗口关闭、Ctrl+C 和分级终止等外部副作用。
- `src/Maintenance` 管理软件升级保护状态机、证据匹配和会话恢复。
- `src/UI` 管理 ListView 投影、图标资源、交互注册和窗口所有权。
- `src/Diagnostics` 生成不自动上传的本地诊断包。

`src` 模块通过显式构造参数或回调取得依赖，不读取根全局 `App`、`Main` 或
`GuiModules`。短生命周期 GUI 由类实例拥有；关闭路径必须停止计时器、注销消息、
终止仍属于当前会话的工作进程、释放原生资源，再销毁窗口。

## 目标身份与探活

`TargetSpecsService` 为每个项目生成分离的 `LaunchSpec` 和 `ProbeSpec`。启动规格
只描述如何启动，探活规格只描述如何确认运行；缓存指纹只包含真正影响对应行为的
输入。

普通 EXE 优先用完整镜像路径和 PID 创建身份确认。脚本需要解释器命令行证据。
快捷方式存在时仍从 LNK 启动，但由 `ShortcutTargetResolver` 解析真实目标、内置
参数、MSI 组件和安装目录候选用于探活。快捷方式暂时缺失时，只有已经确认的真实
目标才能作为恢复入口；同分候选不能靠猜测决定。

`ProcessSnapshotService` 为一轮 WMI 快照建立路径、名称和命令目标索引。快照过期、
记录数不一致、字段不可读或进程身份缺失时返回未知，而不是清除已知身份。主动终止
工作进程前还会核对 PID 和创建身份，避免 PID 复用后误杀无关进程。后台结果分别
记录内容发布时间与工作器启动时的请求代际；短时单次计时器只轮询结果文件，不在
界面线程执行 WMI 查询，因此监控间隔再长也不会延迟已完成快照的交付。

## 控制器、调度和竞态

`App.appStates` 中每个值都是独立 `TargetSupervisor`。控制器持有守护阶段、PID
身份、重试计数、代际、快照握手，以及重启和验证任务令牌。重启或启动验证缺少新
快照时只发起一次带代际的异步请求，发布结果必须不早于该请求，并在有限截止时间内
才能唤醒原任务；证据永久不可读时不会伪装成瞬态等待。暂停、删除、修改启动或探活
输入、撤销、升级保护和应用退出都会推进代际并清除握手；同一路径随后重新添加也不
会接纳旧回调。

所有目标共用一个 `WatchdogScheduler`。调度器用按到期时间排序的最小堆和单个可
重置计时器执行任务，避免为每项创建长期计时器。堆操作在短临界区内完成，业务回调
在普通线程状态运行。`GuardWorkGate` 使主监控、升级扫描、目录事件和显式维护命令
原子互斥；门忙时任务短暂重排，不阻塞 UI。

快速重试序列耗尽后，`RestartPolicy` 使用最后一个配置间隔继续低频重试；探活成功
后计数归零。任何可能等待的启动或停止操作前后，运行时都会重新检查控制器所有权。

## 软件升级保护

升级保护默认关闭。开启后使用 `Normal / Arbitrating / Updating / Stabilizing /
Recovering / TimedOut` 状态机。更新进程必须有完整路径、安装根目录、命令行根目录
引用或目标父子链等证据；缓存以“PID 加创建身份”为键，PID 复用不会延长保护。

完成一次伴随目标文件变化的升级后，可以学习绑定作用根的更新程序特征。纯进程名
或没有作用根的路径不能成为永久证据。快捷方式目标迁移时，会先解析最终安装目录，
再校验已学习特征。未完成会话原子保存在 `watchdog.maintenance.ini`，仅在真正存在
未结束状态时使用。

## 配置与历史

`WatchdogConfigRepository` 独占 `watchdog.ini`。设置、布局和监控项更新先写同目录
临时副本，恢复分区注释并完成全部修改后，再一次替换正式文件。保存事务从有序运行
快照生成到替换文件保持同一边界；失败时保留原文件，并使用单个指数退避任务重试。

EXE 与源码都以 `A_ScriptDir` 为配置根。同目录共用状态，不同目录彼此独立，但全局
互斥锁仍只允许一个运行实例。自身更新检查由独立 PowerShell 进程执行，主线程每
250 毫秒只查看一次原子结果文件；工作进程句柄而不是可复用 PID 决定超时和结束状态。
检查结果必须对应当前版本，并且只要求 EXE、普通源码或 Git 源码各自真正需要的附件。

安装助手等待主进程退出后校验 SHA-256、规范版本、包形态、入口元数据和发行清单，
再按清单替换受管路径；清单禁止包含 `watchdog.ini` 和
`watchdog.maintenance.ini`。新旧清单可以改变目录管理粒度，备份会折叠到共同的
最外层路径；当前入口先复制备份并保留到其它路径就位，最后才从同目录临时文件原子
替换。新版入口必须先通过 `--startup-validation`，随后正式进程还要在配置
读取、窗口装配和守护计时器启动后原子写出带目标版本的就绪信号；短暂稳定观察通过
后才清理备份。安装助手会在启动新版前逐字节快照两个个人配置；超时、提前退出、
信号不符或核心守护未启动都会结束新进程，恢复旧文件或旧 Git 提交，并恢复启动前的
`watchdog.ini` 与 `watchdog.maintenance.ini`（原本不存在的文件会重新删除）。Git 普通
克隆和 worktree 都要求无受跟踪修改，只能快速前进到正式标签。

当前 `[Apps]` 记录只有一个九字段格式：

```text
Enabled|RunAsAdmin|Path|WorkDir|Args|EnvVars|ResolvedTarget|ResolvedTargetManual|ShortcutArgs
```

布尔字段只接受 `0 / 1`，非空文本必须能无损解码。字段数量错误、旧明文格式或损坏
编码不参与目标注册，而是连同相关展示和升级保护原文进入 `[Recovery]`。

撤销与重做基于有序配置快照和逐字段三方合并。撤销只逆转原操作确实改变、且当前仍
保持操作结果的字段，不覆盖操作之后产生的新修改或新学习证据；应用失败时历史项不
移动，可以再次尝试。

## GUI 生命周期与资源

主窗口 ListView 使用隐藏的完整路径列作为行身份，并维护“路径到行”索引。后台状态
更新只查目标行；拖拽排序、删除、改路径和撤销重排后统一重建索引，发现投影不一致时
自动修复。主窗口和应用搜索窗口共用隐藏原生表头的伪表头组件；点击列名只调用原生
ListView 排序器改变当前投影，不修改主列表的自定义顺序或持久化配置。每个字段按
“升序、降序、自定义／来源顺序”三态循环，第三次点击按隐藏稳定顺序列恢复。

`WindowHierarchyManager` 用引用计数租约维护窗口所有权。下级窗口最小化期间临时解除
原生 Owner，避免把主窗口一起最小化；释放最后一个租约后才根据所有者原始可见、启用
和最小化状态恢复交互。显式关闭、创建失败和窗口被外部销毁都收敛到同一幂等清理顺序。

`UiInteractionRegistry` 统一持有按钮、文本输入、悬浮和按下状态。控件销毁时清除所有
引用；不可用按钮不使用手型光标。`IconResourceRegistry` 独占 ImageList、窗口图标、
WIC、SVG 渲染器和 DPI 重建任务；旧图标列表在占用归零后销毁，迟到的 DPI 回调不能
覆盖新代际。

自定义图标支持 ICO、EXE、DLL、CPL、LNK、PNG、JPG、JPEG、JPE、JFIF、BMP、GIF、
TIF、TIFF、WebP、SVG 和 ANI。SVG 优先由锁定版本的 resvg 在内存中栅格化；位图由
WIC 解码为预乘 Alpha 后高质量缩放并居中。GIF 和 ANI 只显示静态代表帧。

## 显示设置热切换

`LocalizationService` 保存请求语言、实际语言、请求内容字体和实际内容字体。设置保存后，
`ApplyDisplaySettingsHot` 在临界区内快照全部目标状态文本，切换语言与字体，再原位刷新
主窗口标题、既有控件字体、六个命令按钮、统计文本、ListView 状态、右键菜单和托盘。
带占位符的动态状态先从旧语言模板还原参数，再用新语言模板渲染；无法证明来源的系统
原文保持不变。内容控件继续使用用户选择的字体；所有按钮从统一交互注册入口取得当前
语言的 Windows 系统 UI 字体粗体，设置切换标签沿用该入口，主窗口底部状态栏在创建和
热切换时单独应用同一字体。系统强调字体的解析不加载随包字体。

“跟随语言默认”先验证指定语言的已安装首选字体能否由 GDI 创建；缺失时按语言加载
随包首选资源：中文使用 PingFang 原始集合，拉丁及西里尔语言使用 SF Pro Text 常规
与粗体，日文使用 Harano Aji Gothic，韩文使用 Apple SD Gothic Neo。首选仍不可用时
按进程私有加载随包 Noto Sans 可变字体或 Noto Sans CJK
原始集合，再失败才使用 Windows 自带字体。
字体路径按安装根目录解析，加载结果与失败结果均缓存；同一资源在多次语言切换中只加载
一次，退出时以 `RemoveFontResourceExW` 对称释放。OFL 与商业授权字体分别进入 SBOM，
商业字体不会被项目自身的开源许可证重新授权。

显示事务不替换 `App`、`GuardRuntime`、调度器、目标控制器、主窗口或 ListView，且不
改变目标代际。短生命周期窗口注册表在主窗口刷新成功后重建，使下次打开的窗口使用
新语言和字体；既有日志保留写入时文本。任一步失败都会恢复旧语言、旧字体和全部状态
文本。轮询计时器只在检查间隔实际变化时重设，与显示切换无关。

## 退出、重载与故障收敛

退出协调器按顺序停止守护和升级协调器、关闭 GUI、释放渲染与私有字体资源、保存待落盘配置，
最后释放单实例互斥锁。每一步独立隔离异常。重新加载会先由独立进程执行启动验证；
验证成功后，接替实例等待旧实例完整清理并释放互斥锁。验证或启动失败时旧实例继续
运行，不进入半退出状态。

周期日志刷新、倒计时和扫描轮询首次失败后会先停表再记录，避免高频异常循环。批量
ListView 更新在 `finally` 中恢复重绘；扫描取消、关闭和失败共用一个会话代际及清理
边界，迟到工作器不能修改新窗口。

## 验证和发布

核心测试覆盖配置边界、三态探活、PID 复用、快捷方式歧义、1000 项索引和调度性能、
控制器替换竞态、升级保护转换、窗口租约、图标格式、诊断包及失败清理。测试运行器在
所有成功和异常路径后比较正式 `watchdog.ini` 哈希。

GUI 测试创建真实圆角按钮、输入框、只读日志区、带图标 ListView 和三级窗口层级，
并通过真实设置保存路径连续切换全部 13 种语言与字体，核对长期对象身份、动态状态、
菜单、控件字体以及 GDI／USER 句柄。CI 执行短时压力测试，每周执行长时测试；物理
显示器、跨显示器 DPI 和高对比度仍按手工矩阵验证。

公开门禁要求非浅克隆，并以锁定 Gitleaks 扫描全部提交，同时拒绝历史中的本地配置、
临时探针和当前文本中的本机绝对路径。发行构建固定 AutoHotkey、Ahk2Exe、依赖 DLL
及随包字体哈希，在 ASCII 虚拟路径编译并运行编译版启动验证。两次构建的 EXE、ZIP
与 SPDX SBOM 必须逐字节一致。便携包附带 SBOM、AutoHotkey 许可证和精确源码归档；
完整 Actions 构建产物保留校验清单与独立 SBOM，并为三个用户版本生成构建溯源。
