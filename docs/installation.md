# 安装、升级与卸载

**简体中文** | [English](en/installation.md)

## 发行包

Release 只提供完整便携 ZIP 和完整源码 ZIP 两个程序版本：

- 完整便携 ZIP 适合希望明确控制安装、备份和迁移目录的用户。必须完整解压，EXE、
  `assets/` 和 `third_party/` 要保持相对位置，不能只复制其中的 EXE。
- 完整源码 ZIP 用于审阅、开发和源码方式运行，要求本机 AutoHotkey v2 x64。

另行提供的 `fonts.zip` 是可选字体资源包，不是第三个程序
版本。它提供首选和 Noto 回退界面字体；需要时先安装到 Windows。程序本身不依赖该包，
也不会从 ZIP 或程序目录私有加载字体。

`v1.0.0` 是自动更新功能加入前的首个公开版本，本身没有更新助手，也不能自行发起
升级。仍在使用 `v1.0.0` 时，需要手动下载并完整替换为 `v2.0.0`；从该版本起，
后续正式版本才可使用设置中的检查更新流程。

完整便携 ZIP 已经包含运行所需的 AutoHotkey 运行时，不要求用户安装 AutoHotkey。
从源码运行才需要 AutoHotkey v2 x64。发行包的 `licenses/sources/` 同时附带与内嵌
运行时精确对应的 AutoHotkey 完整源码归档；版本、提交和哈希记录在
`build-metadata/toolchain.resolved.json`。该文件是本次发布开始时解析并冻结的实际
工具链快照，不是仓库预先指定的 AutoHotkey 或 Ahk2Exe 版本。

通过 Git 克隆源码并需要构建可选字体包时，还必须安装 Git LFS，并在首次克隆或更新后
执行 `git lfs pull`。CJK 字体集合超过 GitHub 普通 Git 对象的单文件限制；如果工作
区中只剩 LFS 指针文件，字体包构建和发行校验会明确失败。便携 ZIP 和源码 ZIP 均不含字体。

“搜索程序”功能要求本机安装并运行 [Everything 官方最新版](https://www.voidtools.com/downloads/)。发行包附带的 `Everything64.dll`
只是连接索引和后台服务的 IPC 客户端，不能替代 Everything 本体；小助手不会在服务不可用时改为本地全盘扫描。守护、手动
选择文件和批量导入指定文件夹不依赖 Everything。

小助手、AutoHotkey 和 Ahk2Exe 使用独立版本号。EXE 版更新完整发行包时会一同更新
内嵌 AutoHotkey；源码更新始终沿用原来的本机解释器，不负责安装或升级它。Ahk2Exe
只存在于正式发布的构建阶段。查看方式和责任边界见
[版本、运行方式与更新责任](versioning.md)。

## 启动设置

打开“小助手设置”的“启动”页，可以创建桌面与开始菜单快捷方式，或创建
最高权限的登录自启计划任务，并设置启动时是否显示主窗口和检查小助手更新。
界面语言、界面内容字体和主题位于“显示”页。
取消开机自启会删除由本程序创建且身份匹配的任务。软件版本、运行形态、实际
AutoHotkey 版本和更新检查位于“关于”页。

编译与源码两种运行形态都受支持：EXE 创建的快捷方式直接指向实际运行 EXE；源码版创建的快捷方式
直接指向小助手主 AHK 文件，由 Windows 文件关联选择 AutoHotkey 解释器。两种快捷方式都会写入小助手专属的
稳定应用身份和 Logo，不会把产品图标关联到共享 AutoHotkey 解释器，也不会影响其他 AHK 脚本的任务栏图标。
既有“解释器 + 主脚本参数”格式的快捷方式只会在完整确认属于本项目后自动迁移。桌面与开始菜单入口会成对创建并
校验，任一入口失败时恢复两处原状态。计划任务仍按当前运行形态保存。桌面、开始菜单和计划任务使用同一个产品名称，
因此只保留一套入口：

- 从另一种形态再次点击“创建”，会更新同名快捷方式。
- “启动”页发现任务属于本项目但指向另一种形态时，会显示“切换”，点击后把任务
  更新为当前形态；陌生的同名任务仍作为冲突处理。
- 自动更新保持入口路径不变时，现有快捷方式和计划任务无需重建。

若同一目录临时同时放置便携 EXE 与源码入口，它们会共用配置，但发行资源和更新清单也
会共用；不要在该布局中分别自动更新两种形态。需要长期保留两套可独立更新的安装时，
请使用不同目录，并在“启动”页为选定的日常入口重新创建或切换快捷方式和计划任务。

## 升级

默认开启“启动时检查小助手更新”，也可在“关于”页立即检查。发现新版后只
提示，不会静默替换；用户确认后按运行形态处理：

- 正式编译版：下载完整 Windows x64 ZIP，使用 GitHub Release API 提供的 SHA-256
  摘要校验后退出主程序，再由临时更新助手替换实际运行目录中的受管文件并重启。
- Git 源码：确认所有受 Git 跟踪的文件没有本地修改，只允许快速前进到正式发布
  标签，然后使用原 AutoHotkey 解释器重启。有本地修改或历史分叉时拒绝覆盖。
- 非 Git 源码包：下载项目生成的独立源码 ZIP，核对 GitHub 提供的 SHA-256 摘要后
  替换受管源码并重启。

归档包在替换中途失败时会恢复已备份的受管文件；其他失败路径也会尽量重新启动
当前入口，并把错误与调用位置写入系统临时目录的
`ProcessWatchdogUpdateErrors.log`。编译版位于 Git 源码仓库内时不会用 EXE 包覆盖
仓库，应从源码入口执行 Git 更新。

也可以继续手动升级：退出旧实例，备份配置，把新包完整解压到新目录，复制配置后
启动，并按 Release 说明核对一次性迁移要求。

发行包永远不包含 `watchdog.ini` 和 `watchdog.maintenance.ini`，覆盖程序文件不会
主动覆盖个人配置或未完成的升级保护会话。当前版本
只接受 README 所述的九字段守护对象格式；无法解析的记录会进入 `[Recovery]`，
不会静默删除。

## 卸载

先在“启动”页取消开机自启，再退出程序，然后删除便携版或源码版目录。桌面和开始
菜单中由用户创建的快捷方式可直接删除；程序不在注册表保存守护列表。已安装到 Windows
的可选字体属于系统字体，应在 Windows“设置 → 个性化 → 字体”中按需单独卸载。
