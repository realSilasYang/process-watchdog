# 安装、升级与卸载

**简体中文** | [English](en/installation.md)

## 发行包

Release 只提供独立 EXE、完整便携 ZIP 和完整源码 ZIP 三种下载。长期使用建议下载
Windows x64 便携 ZIP 并完整解压；独立 EXE 适合快速运行或比对包内程序，源码 ZIP
用于审阅、开发和源码方式运行。便携版中的 EXE、`assets/` 和 `third_party/` 必须
保持相对位置，不能从 ZIP 中只复制 EXE 运行。

`v1.0.0` 是自动更新功能加入前的首个公开版本，本身没有更新助手，也不能自行发起
升级。仍在使用 `v1.0.0` 时，需要手动下载并完整替换为 `v2.0.0`；从该版本起，
后续正式版本才可使用设置中的检查更新流程。

发行包已经包含运行所需的 AutoHotkey 运行时，不要求用户安装 AutoHotkey。
从源码运行才需要 AutoHotkey v2 x64。发行包的 `licenses/sources/` 同时附带与内嵌
运行时精确对应的 AutoHotkey 完整源码归档；版本、提交和哈希记录在
`build-metadata/toolchain.resolved.json`。该文件是本次发布开始时解析并冻结的实际
工具链快照，不是仓库预先指定的 AutoHotkey 或 Ahk2Exe 版本。

通过 Git 克隆源码时还必须安装 Git LFS，并在首次运行或更新后执行 `git lfs pull`。
项目用 LFS 保存完整的随包字体，其中 CJK 集合超过 GitHub 普通 Git 对象的单文件
限制；如果工作区中只剩 LFS 指针文件，界面仍可能回退系统字体，但构建和发行校验会
明确失败。Release 的源码 ZIP 已包含完整字体，不需要安装 Git LFS。

“搜索程序”功能要求本机安装并运行 Everything。发行包附带的 Everything SDK DLL
只负责连接 Everything 服务；小助手不会在服务不可用时改为本地全盘扫描。守护、手动
选择文件和批量导入指定文件夹不依赖 Everything。

小助手、AutoHotkey 和 Ahk2Exe 使用独立版本号。EXE 版更新完整发行包时会一同更新
内嵌 AutoHotkey；源码更新始终沿用原来的本机解释器，不负责安装或升级它。Ahk2Exe
只存在于正式发布的构建阶段。查看方式和责任边界见
[版本、运行方式与更新责任](versioning.md)。

## 通用设置

打开“小助手设置”的“通用”页，可以创建桌面与开始菜单快捷方式，或创建
最高权限的登录自启计划任务，并设置启动时是否显示主窗口、界面语言和界面内容字体。
取消开机自启会删除由本程序创建且身份匹配的任务。软件版本、运行形态、实际
AutoHotkey 版本和更新检查位于“关于”页。

两种运行形态都受支持：EXE 创建的快捷方式直接指向 EXE；源码版创建的快捷方式
指向当前 AutoHotkey 解释器，并把主 AHK 文件作为参数。计划任务也按相同规则保存
当前运行形态。桌面、开始菜单和计划任务使用同一个产品名称，因此只保留一套入口：

- 从另一种形态再次点击“创建”，会更新同名快捷方式。
- “通用”页发现任务属于本项目但指向另一种形态时，会显示“切换”，点击后把任务
  更新为当前形态；陌生的同名任务仍作为冲突处理。
- 自动更新保持入口路径不变时，现有快捷方式和计划任务无需重建。

若同一目录临时同时放置 EXE 与源码入口，它们会共用配置，但发行资源和更新清单也
会共用；不要在该布局中分别自动更新两种形态。需要长期保留两套可独立更新的安装时，
请使用不同目录，并在“通用”页为选定的日常入口重新创建或切换快捷方式和计划任务。

## 升级

默认开启“启动时检查小助手更新”，也可在“关于”页立即检查。发现新版后只
提示，不会静默替换；用户确认后按运行形态处理：

- 正式 EXE：下载完整 Windows x64 ZIP，使用 GitHub Release API 提供的 SHA-256
  摘要校验后退出主程序，再由临时更新助手替换发行文件并重启。
- Git 源码：确认所有受 Git 跟踪的文件没有本地修改，只允许快速前进到正式发布
  标签，然后使用原 AutoHotkey 解释器重启。有本地修改或历史分叉时拒绝覆盖。
- 非 Git 源码包：下载项目生成的独立源码 ZIP，核对 GitHub 提供的 SHA-256 摘要后
  替换受管源码并重启。

归档包在替换中途失败时会恢复已备份的受管文件；其他失败路径也会尽量重新启动
当前入口，并把错误与调用位置写入系统临时目录的
`ProcessWatchdogUpdateErrors.log`。编译版位于 Git 源码仓库内时不会用 EXE 包覆盖
仓库，应从源码入口执行 Git 更新。

也可以继续手动升级：退出旧实例，备份配置，把新包完整解压到新目录，复制配置后
启动，并按 Release 说明核对一次性迁移要求。

发行包永远不包含 `watchdog.ini` 和 `watchdog.maintenance.ini`，覆盖程序文件不会
主动覆盖个人配置或未完成的升级保护会话。当前版本
只接受 README 所述的九字段监控项格式；无法解析的记录会进入 `[Recovery]`，
不会静默删除。

## 卸载

先在“通用”页取消开机自启，再退出程序并删除解压目录。桌面和开始菜单中由
用户创建的快捷方式可直接删除；程序不在注册表保存守护列表。
