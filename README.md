# 进程守护小助手

基于 AutoHotkey v2 x64 的进程、脚本和快捷方式守护工具。它通过进程身份、
快捷方式真实目标和命令行证据判断目标是否仍在运行，并在证据不足时延后决策，
避免重复启动。

## 快速开始

1. 从 Release 下载 `process-watchdog-<版本>-windows-x64.zip` 并完整解压。
2. 运行 `进程守护小助手.exe`。源码运行时执行 `进程守护小助手.ahk`。
3. 点击“添加”，选择 EXE、脚本或快捷方式。
4. 根据目标需要设置工作目录、参数、管理员运行和软件升级保护。
5. 从运行日志确认探活、重启和升级保护的实际判断依据。

发行包不会携带或覆盖个人 `watchdog.ini`。首次运行会创建当前格式配置；仓库
中的 `watchdog.example.ini` 仅用于说明默认值和字段注释。

## 运行要求

- Windows 10 或 Windows 11
- AutoHotkey v2 x64（开发环境当前使用 v2.0.26）
- `third_party/resvg/resvg.dll` 负责 SVG 内存渲染；异常时回退到系统 Shell
- `third_party/everything/Everything64.dll` 为可选搜索加速组件；异常时自动使用后台原生扫描
- 两个 DLL 均固定官方最新版本（或官方源码构建版本），来源、SHA-256、许可证和升级规则见 `third_party/`

## 架构

- `App`：唯一业务模型，持有监控顺序、单项目控制器及共享服务实例
- `Main`：主窗口，只投影 `App` 中的状态
- `GuiModules`：设置、添加、搜索、日志等短生命周期窗口的所有者
- `src/Config`：运行设置、窗口布局、监控列表、展示、升级保护和历史快照模型，以及字段编解码、有序读取、原子事务写入和就地注释恢复
- `src/Core`：守护阶段、`Running / Stopped / Unknown` 三态观察结果、原子共享工作门、单项目 `TargetSupervisor`、独立撤销/重做历史，以及彼此独立并带缓存服务的 `LaunchSpec / ProbeSpec`
- `src/Execution`：目标启动与分级停止执行器
- `src/Inspection`：原生进程检查、后台快照与文件扫描服务、目标文件指纹与完整性检查、三态探活引擎、快捷方式描述及真实目标解析、异步目录变化监听、不可变进程快照索引和命令行目标解析
- `src/Maintenance`：升级保护状态机、更新进程证据匹配、进程身份核验、维护会话编解码和维护编排器
- `src/Platform`：集中管理 Win32 常量
- `src/UI`：主窗口 ListView 投影、图标资源与 DPI 任务、SVG 内存渲染库边界、按钮及输入交互注册表、托管窗口生命周期，以及窗口 Owner 租约、嵌套激活和独立最小化管理
- `src/Diagnostics`：本地诊断包收集、支持文件复制、压缩和临时目录清理
- `app`：`ApplicationState` 服务组合、运行时适配、守护项命令、状态／日志、系统集成，以及设置、添加、搜索、日志等具体窗口；这里可以连接组合根，`src` 仍保持显式依赖
- `app/UI`：主窗口专用图标管线、深色原生控件、圆角按钮／光标交互和深色消息框

每个守护项先由 `TargetSpecsService` 生成一份带指纹缓存的 `TargetSpecs`：`LaunchSpec` 只描述如何启动，`ProbeSpec` 只描述如何确认运行。缓存只受实际启动和探活输入影响，单纯刷新快捷方式检查时间不会重建规格。`ShortcutTargetResolver` 独占快捷方式真实目标发现、MSI 组件解析、参数目标提取、版本信息缓存和安装目录候选评分，并通过显式注入的进程快照解除同分歧义；常见的前后缀更新器不会被当成唯一主程序。`TargetIdentityService` 统一处理精确身份冲突、快捷方式身份刷新、维护目录迁移和目标可用性；它在任何外部解析后重新核对路径映射的控制器实例，先拒绝冲突，再在短临界区中一次提交目标、参数、指纹与维护状态，失败路径不会留下部分写入。快捷方式存在时仍从 `.lnk` 启动，但使用独立保存的真实目标探活；快捷方式暂时缺失时，可从已确认的真实目标恢复启动，且不会丢失快捷方式内置参数。所有探活入口统一返回 `Running / Stopped / Unknown`，没有可靠进程身份、快照过期或候选进程信息不可读时会延后判断，不会清除已知身份、进入停止恢复或盲目拉起新实例。

`App.appStates` 中的每个值都是独立 `TargetSupervisor`。控制器持有 PID 身份、守护阶段、重试计数、代际和重启/验证任务令牌；回调执行前同时核对当前路径映射的控制器实例、代际和任务槽位。暂停、删除、改路径或撤销会使旧令牌立即失效，同一路径随后重新添加也不会接纳旧回调。不同目标不再被一个全局重启锁互相阻塞。

注册完成后不再保留普通对象控制器或旧定时器分支；监控、重启、验证、升级保护和统计只接受 `TargetSupervisor`。启动失败处理必须携带原控制器实例与代际，不能在等待外部操作后从全局路径映射重新取得一个可能已被替换的控制器。

所有控制器共用一个 `WatchdogScheduler`。调度器通过按到期时间排序的最小堆和一个可重置单次计时器执行任务，不再为每个项目创建散落的 BoundFunc Timer。入队、出队和计时器重置使用短临界区保护堆结构，任务回调仍在普通线程状态执行，避免阻塞 UI。快速重试序列耗尽后，`RestartPolicy` 会使用配置中的最后一个间隔继续自动重试；成功探活后重试计数归零，不会永久停留在“启动失败”。

`GuardRuntime` 独占主监控定时器、重启与验证调度入口，并在执行每个异步任务前核对路径映射、控制器实例、代际和任务令牌。重启与验证回调也必须获取共享工作门；门忙时重新排队 100 毫秒，不阻塞 UI，主监控在已持门时直接调用核心实现。调度入口会拒绝已暂停控制器，状态投影同时校验实例、代际和启用状态；修改管理员要求、真实目标或运行参数会先推进代际并取消旧任务。它只通过注入的探活、服务、启动、配置和状态投影接口访问外部能力；同路径删除后重建、暂停、撤销或进入升级保护时，旧任务无法继续修改新控制器。关闭应用时由它依次停止主监控、取消控制器任务、关闭共享调度器并清理升级编排器，迟到的计时器回调会直接退出。

`GuiModuleRegistry` 统一关闭短生命周期窗口。退出或重载时会先停止日志刷新、搜索与批量导入计时器，终止仍属于当前实例的扫描工作进程，再按所有权由添加窗口关闭服务选择、应用搜索及各自提示窗；搜索模块最后显式释放可选的 Everything DLL。短生命周期窗口用独立注册状态配对安装和注销全局鼠标消息处理器，即使原生窗口被提前销毁，计时器和消息回调也会收敛到同一个幂等 `Close()`，不会留下命中旧实例的回调；主窗口倒计时与 DPI 延迟重建任务由独立的 UI 退出钩子注销。所有批量 ListView 更新都在 `finally` 中恢复重绘；批量导入和原生扫描的启动、轮询、分批消费、取消与失败使用同一清理边界和会话代际，关闭窗口期间才返回的工作器会立即终止，旧会话不能清空或重新启用新会话的控件。异常不会留下周期计时器、禁用控件或活动工作器，取消时已经添加的结果会立即保存；直接拖入的文件与目录扫描结果共用同一数量上限。`IconResourceRegistry` 独占图标缓存、窗口图标对、WIC 工厂、主图标尺寸和 ImageList 占用状态；旧图标列表按占用计数延迟销毁，销毁前只清除对应缓存。连续 DPI 变化使用可取消的代际任务，迟到回调不能覆盖新尺寸或新任务，避免关闭窗口、DPI 切换与图标读取交叉。周期日志刷新和主窗口倒计时首次失败后会先停表再记录错误，避免形成高频异常循环。

主窗口自定义图标支持 ICO、EXE、DLL、CPL、LNK，以及 PNG、JPG、JPEG、JPE、JFIF、BMP、GIF、TIF、TIFF、WebP、SVG 和 ANI。选择 EXE、DLL 或 CPL 后会继续打开 Windows 图标资源选择器，保存并精确提取用户选择的资源项，不再固定使用可能为空白的第 0 项。位图由 WIC 解码为预乘 Alpha 后按 DPI 高质量缩放、保持纵横比并居中填入透明单元格；无 Alpha 的 BMP 若具有一致的连通浅色边缘，会只抠除该边缘底色并保留被轮廓包围的浅色内容。SVG 优先由固定版本的 `resvg.dll` 直接解析到内存中的预乘 BGRA，支持透明度、渐变、遮罩、文本和嵌入式栅格图片，不启动外部程序、不写中间 PNG；DLL 缺失、架构或导出不符、文件过大、解析失败时才回退到系统 Shell 的黑白底双渲染，并拒绝 Shell 返回的通用白页图标。GIF 和 ANI 在 ListView 中显示静态代表帧，不播放动画；WebP 需要系统具备对应 WIC 编解码器或 Shell 缩略图处理器。

应用只注册一个退出协调器，并在任何命令行模式可能提前退出前完成注册。协调器显式按顺序停止核心守护与升级协调器、关闭 GUI 和渲染资源，最后保存待落盘配置并释放互斥锁，避免旧实例仍在清理时提前开放单实例入口；每一步独立隔离异常，并兼容权限失败、重复实例和启动验证等尚未创建主窗口的早期退出路径。重复实例退出与普通退出共用资源入口，句柄关闭后立即清零，不保留可被重复关闭的旧值。重新加载先由独立进程解析并执行当前脚本的启动验证，验证成功后启动携带旧 PID 的接替实例；接替实例等待旧实例完整执行退出清理并释放互斥锁后才获取锁。解析、退出注册或接替进程启动失败时，旧实例保留完整运行时并恢复主窗口。窗口图标的小尺寸和大尺寸句柄必须成对加载成功后才替换，旧句柄只在窗口接纳新句柄后释放；图标缩放的 Shell/WIC 接口、DC、位图和文件对话框的原生内存都通过失败路径清理边界回收。

`WatchdogConfigRepository` 独占主配置文件路径。设置、布局和守护项保存都先复制到同目录临时文件，在临时副本中完成全部分区更新和注释恢复后一次替换正式文件；失败时删除临时文件并保留原配置。守护项保存从运行态取完整快照到替换配置文件处于同一个临界事务，不能被嵌套 GUI 保存插入并误把较新的改动标记为已落盘。字段解码必须通过 UTF-8 往返校验，无法无损还原的值不会被替换成乱码。守护项保存失败后只启动一个 5～60 秒指数退避的单次重试，成功即取消，退出前再做最后一次落盘；正常状态没有额外轮询。`[Apps]` 始终按用户可见顺序读写，无法解析的记录会原样转存到 `[Recovery]`；已有恢复记录在后续启动和保存中继续原样保留，不会被静默删除或重复编码。

`RuntimeSettingsService` 统一管理设置默认值、边界校验、加载回退、事务保存和运行态应用；`WindowLayoutService` 对窗口及列宽执行独立的整数和安全范围约束。`WatchlistPersistenceService` 独占当前九字段监控项格式、三个关联分区、显示顺序和恢复记录的编解码。布尔字段只接受 `0 / 1`，当前格式中的非空文本字段必须是可无损解码的 `<HEX>`；空监控记录、旧式明文字段和损坏编码不会参与目标注册，而会连同对应升级保护及展示原文进入 `[Recovery]`。更换配置仓储时由 `ApplicationState.SetConfigRepository()` 同步更新全部持久化服务，避免测试或故障恢复写入错误文件。

`DisplayConfigCodec` 和 `MaintenanceConfigCodec` 独占展示与升级保护配置的默认值、规范化、克隆、比较和持久化协议，通过显式注入的路径及目标规则工作，不读取全局 `App`。快捷方式快照先以已解析的真实目标确定最终安装目录，再按该目录重新校验已学习的更新程序特征，避免目标迁移时误删仍有效的限定特征。`MaintenanceSessionCodec` 独立负责未完成升级会话的无损往返，损坏字段只回退对应默认值，不把解析职责泄漏回主脚本。

`AppConfigSnapshotService` 统一生成、规范化和比较有序监控项快照，并对展示及升级保护配置执行逐字段三方合并：撤销只逆转被记录操作实际改变且当前仍保持原值的字段，不覆盖操作之后产生的新修改或新学习的更新程序证据。快捷方式快照使用真实目标校验升级保护支持性，不会因为入口扩展名是 `.lnk` 而误关保护。`AppConfigHistoryService` 独占有界撤销/重做栈；只有差异应用成功后才移动历史项，应用异常时原记录保留，可再次尝试。

`MaintenanceCoordinator` 独占升级保护的监听器池、进程基线、显式维护命令队列和两个后台循环，并驱动每个 `TargetSupervisor` 内的升级状态机。两个计时器按事务启动，第二项失败会撤销第一项；关闭时每项停表彼此隔离，未完成初始化的实例不会写入空维护日志。主监控、升级进程扫描、升级文件事件和显式维护命令通过同一个 `GuardWorkGate` 原子互斥，避免定时器或跨进程命令抢占期间并发修改控制器；所有循环都在 `finally` 中释放工作门。监听订阅的注册和移除同时核对路径与控制器实例，旧实例不能删除同路径新实例的订阅；配置根目录失效时会释放旧订阅，单个监听器抛错时只关闭该实例并继续执行其他目标的指纹复核。协调器关闭后拒绝重新初始化、迟到命令、快照发布和监听器重建。所有后台状态写入和后续调度也携带预期控制器，拒绝删除后重建产生的旧结果。快照发布直接回调编排器，不再经过主脚本的影子入口。维护会话的恢复与原子保存也由编排器负责，失败后由现有事件循环低频退避重试，主脚本不直接读写维护日志。

外部副作用集中在 `src/Execution`。`TargetLauncher` 根据 `LaunchSpec` 构造批处理、AHK、PowerShell 或直接启动命令，并负责工作目录与临时环境变量恢复；仅在目标确实配置了自定义环境时，才用短临界区隔离父进程环境，普通启动不增加该开销。`TargetStopper` 依次尝试窗口关闭、Ctrl+C、常规强制终止和提权终止。主守护流程只做控制器实例、代际和阶段决策，每次可能等待的执行调用前后都会重新核对所有权。手动重启期间若项目被暂停、删除、撤销或进入升级保护，旧操作不会继续写回状态或启动目标。

主线程只执行快速的原生探测和 UI 更新。`ProcessInspector` 统一封装 Toolhelp 快照、完整镜像路径、创建身份和提权状态读取，并作为 `App` 持有的单一实例注入探活与升级进程匹配。`TargetFileInspector` 统一计算升级目标指纹、验证脚本非空与 PE 头完整性，并用分隔符边界判断安装根目录，仍被写入方独占、缺失或结构未完成的文件不会触发恢复启动。`ProcessSnapshotService` 独占 WMI 工作进程、PID 创建身份、原子结果文件、重试窗口、最新快照和索引缓存；强制刷新会使旧证据整体失效，并复用同一轮已经启动的工作进程。工作器启动先登记“正在启动”占位，输出路径生成或 `Run` 失败也会在 `finally` 中释放占位；`Run` 返回后再次核对服务终态，退出期间才创建成功的子进程不会被写回已关闭服务。服务关闭后会清空证据并拒绝显式启动、自动获取、强制刷新及迟到快照发布。WMI 进程命令行查询、磁盘搜索与批量导入均在隐藏的短生命周期工作进程中执行，通过 UTF-16 临时文件原子交付结果；每次工作器启动都附加实例内递增序列号，即使固定时钟下连续重启也不会复用结果路径。读取端核对格式头和声明的记录数，缺行、坏行或数量不符时整批拒绝，不使用部分结果。主动终止工作器前必须同时取得已保存和当前的非空创建身份并完全匹配；身份不可读时不会结束可能已复用 PID 的无关进程。文件扫描工作器同时具有自身扫描超时和父进程等待上限，即使 PID 被复用或结果文件丢失，GUI 也会停止轮询并完成失败清理。每份 WMI 快照只构建一次路径、名称和命令目标索引并在本轮复用；过期或证据不完整的快照不会被解释为进程已停止。安装目录监听器按规范化根目录共享，再把变化定向分发给订阅目标。

主窗口以隐藏的完整路径列作为行身份，并维护 `Path -> Row` 投影索引。每秒倒计时和后台状态变化只核对目标行，不再为每个变化扫描整个 ListView；新增行增量登记，拖拽、删除、改路径和撤销重排后统一重建。查询发现行内容与索引不一致时会自动重建，避免结构事件遗漏后更新错行。

窗口所有权由 `WindowHierarchyManager` 以引用计数租约统一维护，`ManagedWindow` 通过启动时显式注入的生命周期适配器使用层级管理、交互复位、临时窗口隐藏、控件注销和图标释放能力，不读取根全局。嵌套窗口关闭时只恢复直接上级并激活仍可见的最上层下级；最后一个租约释放后才按所有者原始启用、可见和最小化状态决定是否恢复交互与前台。下级窗口最小化期间临时解除原生 Owner，完成后立即恢复，因此不会把主窗口作为同一激活组一起最小化。重复子窗口租约使用独立引用计数，失效句柄、重复释放和畸形租约都不会遗留幽灵锁。显式关闭、租约获取失败及原生窗口被外部提前销毁都会收敛到同一幂等清理顺序：释放直接所有者、注销控件、销毁窗口、释放图标，最后恢复正确的前台层级。

`UiInteractionRegistry` 统一持有全部按钮和文本输入目标、当前悬浮及按下句柄、失效按钮清理节流状态和系统光标缓存。控件销毁或 GUI 关闭时通过同一幂等注销入口清除交互引用，按钮移除会同时清空指向该句柄的按下和悬浮状态；光标加载失败不会写入缓存，后续悬浮可以重试。按钮自绘、可用性判断、鼠标捕获以及抬起后执行策略由 `app/UI/InteractionPresenter.ahk` 统一实现，根脚本只注册 Windows 消息入口。GDI+ 初始化期间显式持有 `gdiplus.dll` 模块引用，关闭后释放并清空令牌，支持同进程重新初始化。

升级保护使用独立的 `Normal / Arbitrating / Updating / Stabilizing / Recovering / TimedOut` 状态机。更新进程必须由完整路径、安装根目录、命令行根目录引用或目标父子链等证据命中；运行期缓存以 `PID:创建身份` 为键，快照短暂缺少路径证据时只保留仍能核对创建身份的记录，PID 被复用后不会延长升级保护。完成一次确认过文件变化的升级后，可学习 `P:<完整路径>|R:<作用根目录>` 格式的限定特征；纯进程名和未绑定作用根的路径不会作为永久证据。

## 配置格式

`watchdog.ini` 的 `[Apps]` 当前字段顺序为：

```text
Enabled|RunAsAdmin|Path|WorkDir|Args|EnvVars|ResolvedTarget|ResolvedTargetManual|ShortcutArgs
```

读取和写入都只接受这一个 9 字段格式，不使用版本标记、旧字段分支或兼容包装。字段数量错误或内容无法解析的记录不会被静默删除，而会保留到 `[Recovery]` 并写入运行日志。

`watchdog.maintenance.ini` 只保存尚未结束的升级保护会话，可以为空。

## 构建与发布

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build-release.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\reproducible-build.ps1 `
  -OutputDirectory .\artifacts\validation
```

脚本会下载并校验固定版本的 AutoHotkey 与 Ahk2Exe，随后再次核对实际可执行
文件及 AutoHotkey 许可证哈希，在 ASCII 虚拟构建路径中编译并执行编译版启动
验证。发行输出包含确定性 ZIP、独立 SPDX SBOM 和同时覆盖两者的
`SHA256SUMS.txt`。可复现构建测试使用独立输出目录连续构建两次；相同输入必须
产生相同的 ZIP 与 SBOM SHA-256，且不会因另一个已运行发行版锁定默认产物目录
而误报失败。标签发布还会为三个发行文件生成 GitHub 构建溯源证明。
